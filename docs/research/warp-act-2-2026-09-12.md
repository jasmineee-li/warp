**WARP - Act 2**

Since August 8, I've been expanding WARP beyond our 50-task release for a main-conference submission. The work adds more demanding workflows and fixes problems in how we run and score attacks. It also sets up a controlled test of whether transcript-purpose (TP) feedback helps improve attacks. The implementation PRs have merged. The expanded model experiments are next.

WARP tests attacks hidden in web content an agent encounters during a legitimate task. An agent that recognizes a test may behave differently in deployment. Our original bank covered three action families, so we also need to test a wider range of tasks.

**What I've done**

- Brought the existing Taskgen authoring code onto `main` and preserved the history of its source and results. Each site's code now owns its generation and attack-placement rules. Visibility checks and scoring live with the site code, along with its restoration rules. This makes the requirements for a new workflow easier to follow. [Cutover](https://github.com/jasmineee-li/warp/pull/41)

- Made runs easier to pause and resume from saved checkpoints. Settings persist, and status explains which cached work can be reused and where each stage stands. Runs also track costs and check ownership. Small provider checks run before larger jobs resume, helping us catch failures before repeating expensive work. [Run control](https://github.com/jasmineee-li/warp/pull/79), [provider checks](https://github.com/jasmineee-li/warp/pull/264)

- Split large modules and tests into smaller pieces and improved the study's type checks. Changes to CI reduced the measured critical Taskgen test job from 138 to 90 seconds. [CI improvement](https://github.com/jasmineee-li/warp/pull/261)

- Added GitLab tasks where an agent compares records before making a decision or acting on it. Rocket.Chat tasks require following conversation updates or notifying the right person. Both Rocket.Chat families passed live checks using ordinary participant accounts. We independently checked the results and verified resets. These checks ran without a model. [Decision evidence](https://github.com/jasmineee-li/warp/issues/210), [notification evidence](https://github.com/jasmineee-li/warp/issues/211)

- Added an optional Rocket.Chat task that puts owner and deadline corrections in separate messages. The agent must combine both to answer. This task is outside the frozen bank. I also completed a one-task Classifieds listing-reply pilot using response-label scoring. [Partial-update pilot](https://github.com/jasmineee-li/warp/pull/372)

- Built the matched rewrite experiment. Each eligible baseline gets one TP-guided rewrite and one ordinary-critique rewrite, with the same opportunity and repair allowance. The TP arm gives the rewriting model feedback on whether the interaction looks like an evaluation. We then measure the browser agent's behavior. The order is balanced across pairs. Analysis keeps failed and missing outcomes. It also records costs and estimates uncertainty. The first real pair and the full cohort still need to run. [Arm order](https://github.com/jasmineee-li/warp/pull/340), [analysis](https://github.com/jasmineee-li/warp/pull/341)

- Fixed Reddit/GitLab scoring for new runs to check the content of the resource the agent actually created. I also fixed redirect tracking in browser request capture. The historical audit covers all 300 model-task rows. Some evidence conflicts with the recorded outcomes, so I need to check whether those scores require correction. The original scores are unchanged. [Scoring repair](https://github.com/jasmineee-li/warp/pull/351), [historical evidence](https://github.com/jasmineee-li/warp/blob/main/docs/research/web-benchmark-onboarding-2026-08-30/offline-evidence-2026-09-07.md)

- Found that initialization could leave created records behind. I added restoration that gives one run exclusive control of an instance. Tests on disposable instances passed. Before the larger runs, we need to confirm the research starting state and put restoration into use on those instances. [Restoration](https://github.com/jasmineee-li/warp/pull/371)

- Saved the exact prepared requests used in ordinary planning and payload generation. Default iterator rewrites now retain them too, so we can trace requests to outcomes during an audit. [Planning](https://github.com/jasmineee-li/warp/pull/362), [generation](https://github.com/jasmineee-li/warp/pull/360), [rewrites](https://github.com/jasmineee-li/warp/pull/364)

- Recovered supporting artifacts and traced the sources behind the classifier and probe results. I corrected the GUI-Owl vision-path descriptions. In the manuscript, I fixed the bibliography and restored the missing architecture figure. We still need to match some awareness claims to the settings and outputs that produced them, including their denominators. [Study follow-ups](https://github.com/jasmineee-li/warp/issues/308), [bibliography](https://github.com/jasmineee-li/worldsim-paper/pull/8), [figure](https://github.com/jasmineee-li/worldsim-paper/pull/9)
