**WARP - Act 2**

September 16, 2026

Since August 8, I've been expanding WARP beyond our 50-task release for a main-conference submission. The goal is to test agents on more demanding workflows and measure whether evaluation-awareness feedback helps improve attacks. Most implementation work has merged. The expanded model experiments are still ahead.

**New Changes:**

- Some Reddit/GitLab scoring paths could count text from an existing record as evidence that an attack succeeded. I fixed scoring for new runs to check the content of the resource the agent actually created. This makes the success measure match the action we claim to test. The audit covers all 300 historical model-task rows, with evidence conflicts still under review before any score corrections. [Scoring repair](https://github.com/jasmineee-li/warp/pull/351), [historical audit](https://github.com/jasmineee-li/warp/blob/main/docs/research/web-benchmark-onboarding-2026-08-30/offline-evidence-2026-09-07.md)

- The original 50-task bank covered three action families on GitLab and Postmill. I added GitLab comparison tasks and Rocket.Chat conversation workflows, so we can test agents making decisions from multiple records and changing information. Rocket.Chat passed live checks without a model, including saved-result and reset checks. An optional task splits owner and deadline corrections across messages. I also tested one listing-reply task on Classifieds, a separate web application for classified ads. These additions give us a way to test whether WARP's results extend to more demanding tasks and another application. [Rocket.Chat evidence](https://github.com/jasmineee-li/warp/issues/210), [partial-update task](https://github.com/jasmineee-li/warp/pull/372)

- The earlier rewrite results did not isolate the benefit of evaluation-awareness feedback from the benefit of rewriting itself. I built a comparison that gives each baseline one transcript-purpose (TP) rewrite and one ordinary-critique rewrite, with equal opportunities. Execution order is balanced, and the analysis keeps failed or missing results. This lets us measure whether TP feedback actually helps. The first real pair still needs to run. [Study analysis](https://github.com/jasmineee-li/warp/pull/341)

- Initialization could report success while leaving created records behind, allowing one run to affect the next. I added exclusive control of each instance during restoration and checks that the records were removed. Tests passed on temporary servers. This gives us a tested reset path for independent comparisons. We still need to confirm the starting data and enable it on the AWS servers used for experiments. [Restoration](https://github.com/jasmineee-li/warp/pull/371)

- Taskgen's working code and the public package had separate development histories that needed reconciliation. I brought development onto `main` and put each site's rules together, making it easier to extend the same code we test and share. Better checkpoints and run diagnostics make paid work easier to resume and debug. The main automated test job fell from 138 to 90 seconds, shortening the feedback loop for each change. [Implementation history](https://github.com/jasmineee-li/warp/compare/612216a9e55591c827f3215988fdae1787180575...5be19222)

- Some awareness claims were difficult to trace to their original outputs, and model requests were not consistently retained. I recovered classifier/probe evidence and corrected the GUI-Owl vision-path descriptions. Supported generation and rewrite paths now save their requests, making future results easier to audit. I also repaired the manuscript's bibliography and missing figure. Matching the remaining claims to their settings and results will let us update the paper from evidence we can inspect. [Paper follow-ups](https://github.com/jasmineee-li/warp/issues/308)
